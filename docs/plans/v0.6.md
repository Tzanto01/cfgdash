# Plan: v0.6 (assistant that edits, editable files, panel polish)

Owner: department lead. Source: Nico, 2026-11-03. Status: decisions taken by Nico on 2026-11-03 (all three recommendations): assistant auto-apply covers settings keys only; text config files are editable (instructions, agents, skills, commands, settings JSON; hook scripts and the rest stay read-only); providers: Claude now, picker ready for more.

## Items

1. **Budget toggle.** cfgdash settings get `assistant.budgetEnabled` (default on). Off means no `--max-budget-usd`; the 10-minute, 40-tool-call and two-process limits stay. The gear shows the cap field only while it is on.
2. **Assistant may apply (\*).** A new opt-in `assistant.applyEnabled` (default off). When on, the assistant's `propose_change` applies directly instead of waiting for Nico's confirm. It still goes through validation and the assistant policy, is audited with `origin: assistant`, and shows in the change log with Undo. This lifts the "explicit confirm" rule in AGENTS.md for this one opt-in, so it needs Nico's ruling and an AGENTS.md line.
3. **Editable files (\*).** The file viewer gets an Edit mode for registered files of an agreed set, with the same propose, diff, confirm, audit and undo path as edits-v1 (a new `edits-v2` file target). Never: credential files, never-read files, other apps' databases, git state. Which file kinds are in the set is Nico's call; AGENTS.md lists instructions, agents, skills and hooks as never written today.
4. **Context feedback.** Each context chip shows its state: added, not found, not allowed (the assistant allowlist or the company filter) or too large. The server reports per reference what it resolved. The "Some attachments could not be attached properly" message is not cfgdash's text; it seems to come from the Claude CLI or T3, so the team reproduces it first and maps it to a clear message.
5. **Resizable panel.** A drag handle on the panel's inner edge, min 320 px, max 60 % of the window (or the width minus 480 px for the main view, whichever is smaller), keyboard resizable, width remembered per browser. Ultrawide gets the room.
6. **Diagnose all.** A button on the Health view that opens the panel and runs the full check over the current findings, with each fix as a proposal (or applied, when item 2 is on).
7. **Code blocks in answers.** Each block gets Copy and a Wrap toggle (default wrap on for one-line YAML and settings text).
8. **Model picker (\*).** A T3-style popover: providers on the left, the model list in the middle with search, reasoning effort on the right. The same component replaces the plain inputs in the gear. Which providers it lists is Nico's call: each new runtime (Codex, OpenCode) needs its own containment design and security review like assistant-v1.

## Contracts

- `cfgdash-config-v1`: `assistant.budgetEnabled`, `assistant.applyEnabled`, `assistant.provider`.
- `assistant-v1` rev 3: apply mode, per-reference context results, the Health "diagnose" entry point.
- `edits-v2` (new): file targets for item 3.
- AGENTS.md: the write exceptions Nico accepts for items 2 and 3.
