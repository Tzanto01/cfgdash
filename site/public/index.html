See what your Claude Code harness actually loads.

cfgdash reads the settings, instructions, agents, skills, hooks and MCP servers on your machine and shows which file set each value and which layer won. One executable, local only, read-only by default.

cfgdash

Serves on http://127.0.0.1:7820 and opens your browser.

One harness, many files

Claude Code builds its behavior from settings in four layers, instruction files from several folders, and a growing set of agents, skills, hooks and MCP servers. When something behaves differently than you expect, the answer is somewhere in those files.

  1. 1

    Four layers, one effective value.

    Managed, local, project and user settings merge per key. cfgdash shows the winner, the file it came from and what it overrode.

  2. 2

    Instructions load from many places.

    cfgdash shows the chain for a folder in load order, with sizes and token estimates, including imports.

  3. 3

    Broken config fails quietly.

    A hook whose script is gone, an agent that loses to a duplicate, an MCP command that is not on PATH. Health lists each one with its evidence.

Local by design

cfgdash looks at files that hold your tooling's secrets, so the rules are strict and written down.

listens on
127.0.0.1 only. Never a LAN address.
access
A fresh random token for every run, in the URL it prints.
secrets
Credential files are never opened. Secret-looking keys and values are redacted before anything leaves the core, and over-redaction is the accepted failure mode.
writes
Nothing by default. Edits work only from localhost, after a diff and an explicit confirm, and every one is audited and undoable.
network
The UI loads nothing from outside its own origin: no CDN, no remote fonts, no analytics.
idle
It stops itself after 30 minutes without a request.
tailnet
Optional. --tailnet publishes through Tailscale Serve to your own tailnet, and every request needs the token plus a tailnet identity. Never Funnel.

One command

A single self-contained executable for Windows x64 and Linux x64. No runtime to install.

  • $ cfgdashServe on 127.0.0.1:7820 and open the browser
  • $ cfgdash --dir <path>Start in another folder
  • $ cfgdash --tailnetAlso publish to your tailnet
  • $ cfgdash doctorPrint health findings; exit code 3 on a critical one
  • $ cfgdash contextPrint what the harness loads for a folder
  • $ cfgdash exportWrite a snapshot as JSON
  • $ cfgdash autostart onStart at login
  • $ cfgdash updateInstall the latest release
  • $ cfgdash stopStop the running instance

Questions

Does it change my configuration?

Not unless you ask it to. Viewing never writes. The edit path is separate: it works only from localhost, shows a dry-run diff, applies after you confirm, logs the change and can undo it.

Does anything leave my machine?

The dashboard itself makes no outside requests. Two features talk to other systems when you use them: the config assistant starts a session with your own Claude CLI, which sends the redacted data it reads to your model provider, and cfgdash update downloads the next release.

Do I need Tailscale?

No. It is only needed to open the dashboard from your other devices (--tailnet) and to compare machines in Fleet.

What if my machine only has part of this?

cfgdash shows what the machine has. A source that is missing shows as "not on this machine" with the reason, and is never an error.

Which platforms?

Windows x64 and Linux x64.

Is it open source?

Not at the moment. The repository is private for now.
