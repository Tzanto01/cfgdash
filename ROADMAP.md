# Roadmap

v1 shows the harness of the machine it runs on, read-only. Next, in order:

1. **Fleet view.** Shipped in v0.5.0 (Fleet view, [plan](docs/plans/v0.5.md)); comparing with peers live needs the `tcp:7820` tailnet grant. Discover the other machines with `tailscale status --json`, fetch each one's `/api/v1/snapshot` over the tailnet, show them side by side and as a diff keyed by collector, block and row ids. Needs machine-to-machine auth that works between tagged devices (no user identity header there): a whois-verified peer plus a token exchange, decided before building. Lead with drift, not just side by side: rows that differ between machines first, plus each machine's health findings (12). The same diff also compares this machine against one of its own earlier `cfgdash export` snapshots ("what changed since Tuesday"), which needs no peer auth and can ship first.
2. **Session-audit and transcript insights.** Shipped in v0.2.0 (Sessions view). Read Claude Code transcripts (metadata first), surface loops, missed skills and gates, cost per session; reuse the `session-audit` skill's rubric.
3. **Usage and cost.** Shipped in v0.4.0 (Usage view). Read the existing OpenTelemetry metrics from VictoriaMetrics on the homeserver: tokens, cost and sessions per machine, model and project.
4. **Engram browser.** Shipped in v0.2.0 (Memory view). Metadata first (projects, scopes, topic keys, counts, review dates), content on click, company scope only on machines that have it.
5. **T3 settings.** Shipped in v0.4.0. Show T3 Code providers, projects and per-project settings.
6. **Codex and OpenCode configs.** Shipped in v0.4.0. Collectors for their config files, instructions and skills, same block model.
7. **Guarded edits.** Shipped in v0.4.0 (Edit settings screen, `/api/v2`). The write path: a proposed change renders as a dry-run diff, applies only after explicit confirmation, and lands in an append-only audit log in the cache dir. Separate `/api/v2` surface, off by default. First candidate: the config auto-pull switch (`configAutoPull` in the config repo's `.claude/machine.json`), which the overview already shows read-only.
8. **One-line installer.** `irm <url>/install.ps1 | iex` on Windows and `curl -fsSL <url>/install.sh | sh` on Linux, verifying SHA256SUMS before installing. Open decision: where the script and binaries are served, since the repo and its releases are private (public release repo or public cfgdash, or tailnet-only from the homeserver). If cfgdash is ever meant for other people, this is the first step (public repo plus installer), before any paid tier: most collectors assume this workspace (config repo, Engram, homeserver metrics) and already degrade to "not present", but that needs checking on a stock machine.
9. **Write path with AI diagnosis.** Shipped in v0.5.0 as the config assistant (side panel, `assistant-v1`). Builds on 7 and 12: it starts from the health findings as evidence, so the AI explains a concrete finding and proposes a fix instead of guessing what might be wrong. The configured AI providers (for example headless `claude -p`) diagnose harness problems and propose config rewrites, and every proposal goes through the same dry-run diff, explicit confirmation and audit log. Lifts the v1 read-only rule, so it needs its own plan and a security review before any code.
10. **Redesign.** Shipped in v0.3.0. A whole-UI redesign in React (Tailwind, shadcn/ui, Motion) with the `impeccable` skill and the designer's free component sources: more interesting to look at, more comfortable to move around in, more engaging. Replaces the Angular UI in one cutover. Plan, gates and sequencing against 3, 5, 6, 7: [docs/plans/redesign.md](docs/plans/redesign.md).
11. **Folder context command.** Shipped in v0.5.0. `cfgdash context --dir <path> [--json]` prints a short summary of what the harness loads for that folder: instruction chain, effective settings with their source files, agents, skills, hooks and MCP servers. It is computed live from the existing collectors, so it cannot drift the way a generated orientation script would. A SessionStart hook can inject it. Small slice: a new CLI output over data `cfgdash export` already gathers, no new collector.
12. **Health view.** Shipped in v0.4.0 (Health view, `cfgdash doctor`). One list of everything cfgdash already detects as wrong, each with a severity (critical, warning, info), its evidence (file and row) and a link to where it shows. Deterministic rules over the existing snapshot, no AI and no new collector: hook commands whose script is missing (`missing-script`), `@import` errors (missing, cycle, depth), MCP servers whose command is not on PATH, same-name agents or skills where one silently loses (`duplicate`, `overridden`), settings a higher layer overrides (info only, layering is normal), and collectors that are `unavailable` with their reason. A badge on the nav entry, a count on the overview, and `cfgdash doctor [--json]` with a non-zero exit code on critical findings so a SessionStart hook or CI can use it. Feeds 1 (drift) and 9 (diagnosis). Small slice and a good candidate right after 3, 5, 6, 7.
13. **Undo applied changes.** Revert any audited apply from its backup through the same dry-run diff and confirm. Shipped in v0.5.0.
14. **Browser tests in CI.** Real-exe Playwright journeys (views, one propose/apply/undo, CSP, no foreign requests) on every push. Shipped in v0.5.0.
15. **Cross-tool drift.** Health rules for differences between Claude Code, Codex, OpenCode and T3 on the same machine (MCP servers, loaded instructions). Shipped in v0.5.0.
16. **Assistant that edits, and editable files.** Shipped in v0.6.0 ([plan](docs/plans/v0.6.md)). Opt-in auto-apply of settings keys by the assistant (audited, undoable), text config files editable in the file viewer (`edits-v2`), an optional cost cap, context states, "Diagnose all" on Health, a resizable panel, and a provider and model picker.
